Dưới đây là chi tiết các sơ đồ, hình vẽ và biểu đồ cần bổ sung vào các chương chính

--------------------------------------------------------------------------------
1. CHƯƠNG 3: METHODOLOGY (Phương pháp nghiên cứu)
--------------------------------------------------------------------------------
Chương này cần nhiều sơ đồ lý thuyết và luồng xử lý toán học để giảng viên dễ theo dõi.

* Hình 3.1: Sơ đồ cấu trúc Labeled Property Graph (LPG) y khoa
  - Nội dung vẽ: Vẽ 2 nút tròn thực thể (Ví dụ: Nút "Metformin" nhãn :Entity và nút "Tiểu đường" nhãn :Entity) nối với nhau bằng mũi tên có nhãn ":REL" hướng từ Metformin sang Tiểu đường. Trên các nút và cạnh vẽ các hộp thoại nhỏ chứa các thuộc tính (Properties) như:
    + Nút Metformin: {canonical_name: "Metformin", type: "DRUG", aliases: ["glucophage"]}
    + Nút Tiểu đường: {canonical_name: "Đái tháo đường", type: "DISEASE"}
    + Cạnh nối: {predicate: "TREATS", confidence: 0.95, evidence_chunk_id: "chunk_105"}
  - Mục đích: Trực quan hóa mô hình LPG so với RDF.

* Hình 3.2: Sơ đồ luồng hoạt động của Bộ định tuyến ý định lai (Hybrid Intent Router)
  - Nội dung vẽ: Dạng Flowchart:
    [Query người dùng] 
       │
       ▼
    <0ms Fast-Path Regex (Có chứa chỉ số & số liệu?)>
       ├──────(ĐÚNG)──────► [direct_db: Bộ đối chiếu chỉ số lâm sàng (0ms)]
       │
       └──────(SAI)───────► [Gọi song song SLM Qwen-2.5-1.5B Classifier]
                               │
                               ├─► (Phân loại: direct_db) ────► [Nhánh direct_db]
                               ├─► (Phân loại: graph_first) ──► [Nhánh Graph-First RAG]
                               └─► (Phân loại: global_summary)► [Nhánh Xã giao / RAG tổng quan]

* Hình 3.3: Sơ đồ quy trình trích xuất NER lâm sàng và Cypher Path Query
  - Nội dung vẽ: Quy trình tuần tự:
    [Câu hỏi đầu vào] ──► [SLM NER (1.5B)] ──► Trích xuất thực thể: Drug("Metformin"), Disease("Tiểu đường")
                                                   │
                                                   ▼
    [Kết quả RAG chính xác] ◄── [Cypher Path Query] ◄── [Ánh xạ Node ID trên Neo4j]

* Hình 3.4: Sơ đồ vòng lặp Agent ReAct với Loop-Guard & Format Recovery
  - Nội dung vẽ: Vòng lặp tuần hoàn thể hiện các bước:
    [User Query] ──► [LLM Generate: Thought -> Action -> Action Input]
                           │                     │
                (Format Error?)           (Repeated Action?)
                           │                     │
                    [Format Recovery]         [Loop-Guard Trigger]
                           │                     │
                           ▼                     ▼
              [Corrective repair prompt]   [Forced Final Answer]

--------------------------------------------------------------------------------
2. CHƯƠNG 4: EXPERIMENT EVALUATION (Cài đặt hệ thống & Thực nghiệm)
--------------------------------------------------------------------------------
Chương này cần các ảnh chụp giao diện hệ thống thực tế và sơ đồ cài đặt hạ tầng.

* Hình 4.1: Sơ đồ kiến trúc triển khai Docker Compose (Deployment Architecture)
  - Nội dung vẽ: Một khối bao quanh đại diện cho "Docker Bridge Network (datn-network)" chứa 3 container:
    + [Container 1: datn-api] (FastAPI port 8000)
    + [Container 2: datn-neo4j] (Neo4j Graph Database port 7687/7474)
    + [Container 3: datn-ollama] (Ollama LLM Engine port 11434)
    Vẽ mũi tên kết nối hai chiều nội bộ giữa các container này.

* Hình 4.2: Ảnh chụp giao diện màn hình tư vấn lâm sàng (Agent Chat Screen)
  - Nội dung vẽ: Ảnh chụp màn hình trình duyệt hiển thị giao diện Web UI lúc Agent đang suy nghĩ và hiển thị cây sơ đồ đồ thị Vis.js sinh động có màu sắc khác nhau giữa các nút thuốc, bệnh, triệu chứng.

* Hình 4.3: Ảnh chụp giao diện phân tích bệnh án (Medical Record Benchmarking)
  - Nội dung vẽ: Ảnh chụp bảng kết quả xét nghiệm được tô màu cảnh báo xanh (bình thường), đỏ (tăng cao), xanh dương (giảm thấp) dựa trên kết quả tự động đối chiếu của hệ thống.

--------------------------------------------------------------------------------
3. CHƯƠNG 5: SOLUTION CONTRIBUTION (Các đóng góp của đề tài)

Chương này tập trung vào số liệu thực nghiệm và các biểu đồ so sánh hiệu năng.

* Hình 5.1: Biểu đồ cột so sánh quy mô Knowledge Graph trước và sau khi Pruning
  - Nội dung vẽ: Biểu đồ cột nhóm (Grouped Bar Chart) hiển thị:
    + Cột 1 (Số lượng thực thể): Trước Pruning (46,527) vs Sau Pruning (25,319)

  - Ý nghĩa: Chứng minh tính hiệu quả của thuật toán Pruning loại bỏ nhiễu.

* Hình 5.2: Biểu đồ so sánh độ trễ phân loại tin nhắn (Router Latency Comparison)
  - Nội dung vẽ: Biểu đồ cột biểu diễn thời gian phản hồi (giây):
    + Cột 1: Llama-3.1-8B (Unified Model) -> 2.4s

  - Ý nghĩa: Chứng minh việc chia tải mô hình song song giúp giảm hơn 50% độ trễ.
