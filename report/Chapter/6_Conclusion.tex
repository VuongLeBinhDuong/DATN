\section{Conclusion}
This thesis presented the updated design and implementation of a localized Smart Medical QA \& Consultation System. The system combines FastAPI, local LLM backends, Neo4j/GraphRAG retrieval, ReAct-style agent reasoning, multi-format medical-record analysis, medication utilities, and a browser-based user interface. Compared with a simple chatbot, the current project supports a broader clinical-support workflow: users can ask medical questions, inspect graph-grounded answers, upload laboratory reports, check abnormal values, look up medication-related context, and create reminders.

A major result of the project is its modular architecture. The codebase separates API routes, services, repositories, agent logic, core infrastructure, knowledge-graph utilities, LLM pipelines, medical-record processing, web UI, scripts, and evaluation code. This separation makes the system easier to maintain and improves the ability to test individual behaviors. It also allows future replacement of components such as the LLM backend, graph backend, parser, or UI without rewriting the whole system.

The retrieval and graph components address the hallucination problem by grounding answers in external context. Instead of asking the model to answer only from memory, the agent and API can retrieve evidence from Neo4j or GraphRAG-oriented modules and include source metadata. The custom KG utilities also make it possible to ingest documents, extract entities, extract relations, normalize predicates, and load graph data into Neo4j. The verified artifact set currently contains 39,989 documents, 117,418 chunks, 17,338 entities, 68,311 mentions, and 78,705 relations, giving the system a concrete foundation for explainable medical answers.

The ReAct agent provides a second important result. It can reason over a user query, call tools, observe results, and synthesize a final answer. More importantly, the implementation includes practical safeguards: parser validation, retry prompts, synthetic recovery, maximum iterations, loop protection, forced finalization, and streaming support. These controls are essential when using local LLMs, which may not always follow the requested format perfectly.

The medical-record analyzer extends the system beyond ordinary chat. By supporting PDF and Excel extraction, laboratory parsing, reference-range comparison, abnormality classification, and LLM-based summaries, the project can process realistic healthcare artifacts. The medication and reminder features further connect consultation output with practical user follow-up.

The project remains a research prototype. It is not a certified medical device, and every medical output should be checked by qualified professionals. Nevertheless, the implementation demonstrates that a privacy-aware and explainable CDSS can be built by combining local inference, graph retrieval, deterministic checks, document parsing, and user-centered workflows.

\section{Future Work}
Future development should focus on the following directions: clinical validation by evaluating answer correctness, safety, and usability with clinicians and curated medical benchmark datasets; knowledge‑base expansion by adding more verified Vietnamese and international medical sources, clinical guidelines, drug interaction databases, and specialty‑specific documents; better laboratory interpretation by improving unit conversion, age/sex‑specific ranges, pregnancy‑specific ranges, and lab‑specific reference handling; security hardening by replacing prototype JSON user storage with a production identity layer, stronger token lifecycle management, audit logs, and role‑based access control; persistent reminders by moving browser‑only reminders to an optional backend scheduler for multi‑device synchronization and notification delivery; multimodal input by extending analysis to scanned prescriptions, OCR‑heavy documents, ECG traces, radiology reports, and structured FHIR records; retrieval ranking improvement by improving entity normalization, synonym expansion, and ranking functions; RAGAS evaluator repair by debugging context formatting, evaluator model configuration, and judge prompts; evaluation automation by integrating retrieval benchmarks, graph validation, route tests, prompt regression tests, and latency measurements into a repeatable CI workflow; and human‑in‑the‑loop review by adding clinician review screens so generated advice can be accepted, edited, rejected, and used as feedback data.
